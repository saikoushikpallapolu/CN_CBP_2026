1. WHAT PROBLEM ARE WE SOLVING?
--------------------------------------------------------------------------------

Today, many firewalls and security tools look for "signatures".

  Signature (simple meaning):
    A fixed pattern, like a fingerprint of known malware.
    Example: "if this exact byte pattern appears, block it."

The problem:
  Attackers keep changing malware slightly so the old signature
  no longer matches. Rule-based tools then miss the attack.

Our idea:
  Instead of matching exact rules, we turn network traffic into
  PICTURES, then teach a computer (a neural network) to LOOK at
  those pictures and say:

    - Benign  = normal, safe traffic
    - DDoS    = flood attack (too much traffic on purpose)
    - Botnet  = machines controlled by an attacker

So we treat network security like a computer-vision problem:
"Does this traffic IMAGE look like an attack?"


--------------------------------------------------------------------------------
2. WHAT ARE WE BUILDING? (ONE SENTENCE)
--------------------------------------------------------------------------------

Capture network packets → turn their bytes into grayscale images →
train a CNN to classify: Benign / DDoS / Botnet.


--------------------------------------------------------------------------------
3. IMPORTANT TERMS (SIMPLE EXPLANATIONS)
--------------------------------------------------------------------------------

PCAP
  A file that stores captured network traffic (packets/frames).
  Think of it as a recording of what went over the network.

Packet / Frame
  A small chunk of data sent on the network.
  "Frame" is often used at the Data Link layer (Unit II).

Binary / Bytes
  Computers store data as numbers 0–255 (bytes).
  Raw traffic is just a long sequence of these numbers.

Grayscale image
  A black-and-white picture. Each pixel is one brightness value
  (0 = black, 255 = white, values in between = gray).

2D array
  A grid of numbers (rows × columns), like a spreadsheet.
  We reshape a long list of bytes into a grid, then treat that
  grid as an image.

CNN (Convolutional Neural Network)
  A type of AI model that is good at finding patterns in images
  (edges, textures, shapes). We use it on traffic-images.

TensorFlow / PyTorch
  Two popular libraries for building and training neural networks.
  The team should pick ONE and stick to it.

Training
  Showing the model many labeled examples so it learns.
  Example: "this image is DDoS", "this one is benign".

Inference / Classification
  After training: give a new image → model outputs a label
  (benign / DDoS / botnet).

DDoS
  Distributed Denial of Service — many sources flood a target so
  the service becomes slow or unavailable.

Botnet
  A group of infected devices controlled by an attacker, often
  used for spam, DDoS, or stealing data.

Benign traffic
  Normal, legitimate network activity.

Unit II (Data Link framing)
  Course topic about how data is packaged into frames on the link.
  In our project: how raw frame bytes become structured 2D images.

Unit V (Network Security)
  Course topic about protecting networks.
  In our project: detecting attacks (DDoS / botnet) from traffic.


--------------------------------------------------------------------------------
4. ARCHITECTURE (HOW THE PIECES FIT)
--------------------------------------------------------------------------------

Think of a pipeline — each stage feeds the next:

  [1] DATA INPUT
        Raw PCAP files
        (folder: data/raw/)
              |
              v
  [2] DATA PROCESSING  (Unit II)
        Read bytes from packets/frames
        Convert byte sequence → fixed-size 2D grayscale image
        Save labeled images
        (code: data_processing/   output: data/processed/)
              |
              v
  [3] MACHINE LEARNING  (Unit V — detection)
        Load images + labels
        Train a CNN
        Save the trained model (weights)
        (code: ml/   output: ml/checkpoints/)
              |
              v
  [4] CLASSIFICATION / OUTPUT
        Load trained model
        Predict on new images
        Report: Benign | DDoS | Botnet
        (code: classification/)

Optional helpers:
  notebooks/  — try ideas, plots, experiments (not final product code)
  scripts/    — short commands that run the full pipeline
  docs/       — write-ups, syllabus mapping, design decisions


Visual flow (same as the project poster):

  PCAP binary stream
        → blue data blocks
        → 2D grayscale "traffic image"
        → CNN (convolution + pooling + fully connected layers)
        → screen output: Benign (OK) or Malicious (DDoS / Botnet)

8. DECISIONS YOU MUST LOCK BEFORE HEAVY CODING
--------------------------------------------------------------------------------

Locked starter choices (also copied into docs/design.md).
  These are good defaults for learning + a solid demo — change only as a team.

  1. Image size: 64 x 64
       Why: 4096 bytes fits one clear “traffic picture”; big enough for CNN
       patterns, small enough to train on a normal laptop.

  2. Byte → pixel method:
       Take the first 4096 bytes of each sample (flow/window), pad with 0
       if shorter, truncate if longer; each byte (0–255) = one pixel;
       reshape row-major into a 64×64 grayscale image; save as PNG.
       Why: Simple, matches Unit II “bytes laid out in structure,” and is
       the classic malware/traffic visualization approach.

  3. Classes: benign / ddos / botnet  (3-class, not binary)
       Why: Matches the project poster/abstract exactly and teaches multi-
       class CNN output (not just “bad vs good”).

  4. Framework: PyTorch
       Why: Clear tensors and training loop — easier to learn “what is
       happening” step by step than hiding everything in high-level APIs.

  5. Dataset source: CIC-IDS2017 (start with a SMALL labeled subset:
       Benign + one DDoS scenario + Botnet; full PCAPs from CIC if available,
       or flow/byte exports if PCAPs are too huge at first)
       Why: Public, well-known, has the three labels we need; start small
       so the pipeline works before you download everything.

  6. Success target: test accuracy ≥ 90%, plus per-class F1 score
       Why: Submission/approval bar — 90%+ shows a demo-ready model, not a
       toy; F1 stops one class from looking “fine” while another is ignored.

10. PRACTICAL RULES (AVOID PAIN)
--------------------------------------------------------------------------------

  - Do not commit huge PCAP files or model weights to git.
    Keep them local; document the download/source link in data/README.md

  - Keep image size and label names IDENTICAL across all modules.
    If Role A uses 64x64 and folders named "ddos", Role B must match.

  - Start with a SMALL dataset to prove the pipeline works,
    then add more data to improve accuracy.

  - Prefer simple CNN first. Fancy architectures can wait.

  - Notebooks are for exploration. Final code belongs in the module
    folders so anyone can run it without opening Jupyter.
